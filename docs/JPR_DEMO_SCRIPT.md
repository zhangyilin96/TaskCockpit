# JPR向けデモ進行メモ

このデモはすべて架空データを使用します。正式Workspace、通常デモ、実在する会社・顧客・個人プロジェクトとは分離されています。

## 30秒の導入

> 複数のプロジェクトを並行すると、「前回どこまで進めたか」「次に何をすべきか」を思い出すだけで時間がかかります。Project OSは、長期テーマ、プロジェクト、今回の作業という三つの階層で現在地を残します。AIが情報を整理しますが、勝手に状態を更新しません。人が内容を編集・選択して確認した後にだけ、次回へ引き継ぐ状態が保存されます。

## 3分のデモ

1. JPR専用URLの `jpr-demo.html` を開き、`JPRデモを開始` を押す（0:00–0:20）
   - `業務改善` が長期的なメインテーマとして見えることを示す。
   - 通常版と通常デモは `index.html` に残り、JPRデモとは別ページであることを短く説明する。
   - 伝える価値：複数の案件を、長期方向から迷わず選べる。

2. `業務改善` → `問い合わせ対応の標準化` を開く（0:20–0:50）
   - 本番と同じ状態ラベル、タスクメニュー、`プロジェクトを追加`、Resume構造を使っていることを示す。
   - 目的、現在の目標、現在の状態、完了したこと、進行中、現在の問題、次の一歩を確認する。
   - 伝える価値：前回の会話やメモを探さず、プロジェクトの現在地を短時間で復元できる。

3. `今回の作業を開始` を押す（0:50–1:10）
   - 最大3件に絞られた「今回やること」を見せる。
   - 伝える価値：バックログ全体ではなく、今やる具体的な行動だけに集中できる。

4. `作業をまとめる` を押す（1:10–1:45）
   - 今回の作業を含む日文プロンプトを見せる。プロンプト欄をクリックしてコピーできることを示し、`デモ回答を入力` → `AIの提案を確認` と進む。
   - 伝える価値：AIには現在のプロジェクト、許可された共有背景、今回の作業だけを渡し、JSON形式の構造化された提案を得る。

5. AI提案を人が調整する（1:45–2:15）
   - `完了したこと` が初期状態で選択されていないことを示す。
   - 例として `記憶への追加候補` の選択を外す、または `次の一歩` を少し編集する。
   - `確認して反映` を押す。
   - 伝える価値：AIの出力は提案であり、人の確認なしにプロジェクト状態を変えない。

6. 一時停止と再開性を示し、Sessionを終了する（2:15–3:00）
   - `今回の作業を一時停止` を押してホームへ戻り、同じプロジェクトに「今回の作業は一時停止中」と表示されることを示す。
   - `前回の続きから再開` で同じSessionへ戻り、メモが残っていることを確認してから `今回の作業を終了` → `まとめを保存` と進む。
   - プロジェクトへ戻り、編集・確認した現在地と次の一歩が残っていることを示す。
   - 必要ならページを更新し、JPR Demoが復元されることも示す。
   - 伝える価値：一回の作業結果が次回の再開地点になる。

## まとめの一言

> AIが整理し、人が判断する。プロジェクトの状態は、確認してから更新されます。

## デモがうまく進まない場合

- AI回答が用意できない：`デモ回答を入力` を使い、「実運用では生成したプロンプトを任意のAIへ渡す」と説明する。
- 誤ってダイアログを閉じた：`作業をまとめる` をもう一度開き、貼り付け途中のAI回答が復元されることを見せる。
- Sessionがすでに開始済み：プロジェクト画面の `前回の続きから再開` から続ける。更新後も復元できる証拠として説明できる。
- データを変更しすぎた：右上の `デモをリセット` でJPR Demoだけを空にし、`デモを最初から始める` へ戻る。`JPRデモを開始` を押せば架空プリセットを再読込できる。正式Workspaceと通常デモは変わらない。
- 時間が足りない：ResumeとAI確認画面を優先し、Session終了は「この状態が次回の再開地点として保存される」と画面上で説明する。

## 今回は見せない範囲

- クラウド同期、ログイン、複数人での共同編集
